## Workload and assertions

`crates/pipkin-engine/tests/perf/mixed.rs::mixed_soak` drives one real release worker,
eight attached conversations, and two concurrently active turns per batch. Each of 720
turns executes real bash in a private Git fixture: append a unique turn number to a file,
produce 1 MiB of output plus an identifying suffix, then stream a 64 KiB assistant reply
as 64 marked chunks separated by 10 ms. Normal retained conversation context grows across
90 turns per session. No reset, shortened history, allocator tuning or relaxed durability
is used. The local scripted OpenAI-compatible provider supplies fixed usage; this workload
does not exercise real provider token accounting or automatic compaction under real usage.

The worker exits cleanly and restarts after turns 240 and 480, and once more after turn 720.
At each restart, all eight latest replies reopen with their expected lengths and markers.
Replaying each latest settled admission returns its completed result without another
provider request. Final assertions verify:

- All 720 unique tool effects occurred exactly once in this workload.
- All 720 saved final replies have the expected 64 KiB length and complete ordered markers.
- All 720 complete spill files contain the generated bytes and their unique turn suffix.
- All saved tool results link to distinct existing spill files in the private output directory.
- All 720 durable tool-output rows match the generated output byte for byte, with zero drops.
- Exactly 1,440 provider requests occurred; no run remains unsettled and no finalized
  `entry_chunks` remain.
- Idle file descriptors return to the starting count; no tool descendants remain at each
  sampled settled boundary. The separate 50 ms sampler records transient worker RSS, fds
  and tool descendants; it can miss very short-lived children.

This is engine-only, using the real adapter, runtime, SQLite WAL/FULL durability and framed
client transport. The provider and test client are outside the measured worker. Output
spills use a private `TMPDIR` cleaned up with the fixture. It does not send synthetic desktop
input or use an account, live provider, Pi runtime or Node runtime.

VmHWM is a kernel high-water reading, including short-lived allocations that the 50 ms
sampler misses. All three worker epochs and the final reopen are represented. Two-turn
batch time includes the scripted stream delay; it is not per-chunk latency, UI latency,
or model inference speed. Final run transient sampled maxima: 21 fds and 3 tool descendants.

RSS slopes are positive, not declared flat. Ordinary least-squares slopes over the 16-turn
settled samples, separately for each 240-turn worker epoch, are **9.051 / 5.559 / 6.192
KiB per turn**. Restricting each epoch to its last eight samples gives **5.440 / 3.598 /
3.024 KiB per turn**. Restarts do not justify fitting one cross-process slope. Initial
worker RSS was 26,340 KiB; request construction with growing history raises transient peaks.
The run retains this history and sends 4,259,651,458 cumulative provider-request bytes.
These measurements do not attribute all residual idle growth or prove a bound beyond this
workload. No new allocator/retention fix is inferred.

The final database is **807,088,128 bytes (769.70 MiB)**. This is overwhelmingly retained
content: `tool_outputs.retained` totals **754,984,690 bytes**, all verified against the
unique generated effects, and entry JSON totals **48,466,674 bytes (46.22 MiB)**. Only
29 of 197,043 4-KiB pages are free (0.113 MiB); the outbox is capped at 4,096 rows and
finalized stream chunks are zero. This is not unexplained stream-chunk accumulation or
large free-page retention. The complete spill files separately total 754,984,690 bytes;
the disk cost of retaining both forms is explicit. These are temporary test data, not
committed artifacts.

## Verification and limits

Command:

```sh
OUT=fixtures/native-bench/2026-10-12-mixed-soak-final SKIP_APP=1 \
TESTS='mixed::mixed_soak' scripts/bench-native.sh
```

The first 16-turn smoke attempt failed because the test provider assumed user content was
a string; the native adapter legitimately sent text blocks. The fixture now accepts both
forms. The original failed log is retained as `smoke-initial-failed.log` in the initial full
run directory (trailing whitespace removed). Subsequent 16-turn smoke checks passed, including the final durable-output
and database checks. No engine failure was attributed to that fixture mistake.

The new benchmark is opt-in/ignored in ordinary CI and is now included in the default
`scripts/bench-native.sh` list (nine benchmarks). A passing ordinary workspace run does
not substitute for executing it in release mode.

Required final checks: **1,634 passed, 0 failed, 54 ignored** for `cargo test --workspace`;
`cargo clippy --workspace --all-targets` and `cargo fmt --all --check` clean. The additional
ignored test is the mixed benchmark, explicitly executed twice at full size above.
`bash -n scripts/bench-native.sh` and `git diff --check` also pass. Logs:
`/tmp/pipkin-mixed-workspace-final.log`, `/tmp/pipkin-mixed-clippy.log`,
`/tmp/pipkin-mixed-fmt.log`, `/tmp/pipkin-mixed-soak{,-final}.log`.
The inherited harness's `loadavgStart` field is collected when its result header is built
at the end; use `machine.json` and the runner's pre-test log for starting-load context.

This measures a multi-session streaming/tool-output workload with growing context and
orderly restarts. It is not a desktop soak, a day-long run, a single uninterrupted worker
over all 720 turns, a SIGKILL test, or a general guarantee of exactly-once external effects.
No new hard memory budget is invented for two concurrent contexts; the plan's 100 MiB
budget is defined for its single-active-session workload. Positive slopes remain reported;
bounded samples cannot establish indefinite leak freedom. Longer uninterrupted/desktop
workloads, residual memory attribution, actual compaction under realistic usage, fresh
matched Pi comparisons, installed/rollback, CI/platform and native-default/Pi-removal
qualification remain open. Native remains opt-in; no ledger row is fully qualified here.
